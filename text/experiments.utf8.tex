The goal of the experiments was to determine whether evolutionary algorithms
are suitable for searching S-boxes of chosen sizes.
For this purpose, a comparison with random search was performed.
Comparison of runs according to GAlib statistics \cite{galib} was conducted over multiple runs.
The experiments were scripted in Python.
They were selected based on program testing, where trials were performed with a single run
for different population sizes. For longer-term search of higher quality solutions, the
evolution parameters were first established, especially the mutation and crossover probabilities.
These parameters were then used for more demanding experiments.

\section{Determining Mutation and Crossover Probabilities for Individual Criteria}
First, the crossover and mutation parameters were established for single-criterion
optimization for each criterion. In these optimizations, limit values were usually reached.
The best mutation and crossover probabilities were found for each criterion
with a fixed population size of 100, 1000 generations, and 100 runs.
This was compared against random search with the same number of evaluations.
A moderately complex S-box with 4 inputs and 4 outputs (i.e., type $4 \times 4$) was chosen.
First, all possible probability pairs were tested on the interval $\langle 0, 1)$:
for mutation $0, 0.05, 0.1, 0.2, 0.4, 0.6, 0.8$; for crossover $0, 0.2, 0.4, 0.6, 0.8$.
Because the results for some criteria were similar and not very promising for higher values,
a narrower interval $\langle0, 0.2)$ was chosen. Probability pairs of
$0, 0.04, 0.08, 0.12, 0.16$ were tested for both crossover and mutation.
For each run, the 100 best individuals from the entire evolution were recorded and saved.
All individuals from all runs for one pair $(p_{Mut}, p_{Cross})$ were merged
together and statistics were computed over them.
The results were recorded in tables sorted from worst to best
according to the sorting key (maximum, median, mean + deviation, mean, minimum).
For decision-making, an indicative two-sample t-test was performed on the results of random search
and the best parameter combination for the genetic algorithm.

The box plot in Figure \ref{edaVsGaComparisonBENT_AND_MOSAC} compares individual
algorithms for the bent score criterion. In this criterion, the clear winner is the
Genetic Algorithm. Random search is comparable to EDA algorithms in this criterion.
In criteria $LP_{\max}$ and $DP_{\max}$ (Figs. \ref{edaVsGaComparisonLP_MAX} and \ref{edaVsGaComparisonDP_MAX}),

identical results were achieved. However, in polynomial degree (Fig. \ref{edaVsGaComparisonPOLYNOMIAL_DEGREE}), the genetic algorithm is
worst. Only in this criterion do EDA algorithms perform slightly better than random
search, although the median value is identical.

Overall, EDA algorithms performed worst; random search finds similar results.
The original motivation for deploying EDA algorithms
was the structure of MOSAC Boolean functions, which have certain
regularities\footnote{see Table \ref{miniSAC}, larger functions in \cite{yokohama}}.
A two-input Boolean function (half-byte) satisfying MOSAC contains 3 identical bits, with the fourth differing.
A three-input function (byte) is composed of two-input functions such that the position of the differing bit in the half-bytes is symmetric
about an axis passing through the center of the byte. For a four-input function, two adjacent bytes must not be symmetric.
The question would be whether a probabilistic model of dependencies between bits could be created from this,
which would be usable in evolution using EDA. Against this stands the idea that
a statistical model seeking dependencies between bits has the opposite meaning for security,
because bits should be mutually independent. Therefore, a
more complex probabilistic model for the BOA algorithm was not implemented.

\section{Parameters of Multi-criteria Search}
For a single criterion, practical limit values can be reached quickly and with little difficulty.
However, what do the results look like and which parameters performed best when
all criteria need to be satisfied simultaneously is discussed in the following subsection.
First, it was necessary to determine how to compare results for each pair of mutation and crossover probabilities.
The approach chosen was to count
all above-average individuals.
The average individual was calculated from all runs for all parameters, i.e., after performing
all necessary evolutions, average values were calculated for each criterion and from these
a vector with the same dimensions as the evaluation of any actual individual was created.
For each pair of mutation and crossover probabilities, individuals were counted
who weakly dominate this "average individual."
All criteria examined in previous subsections were used,
namely bent score, $LP_{\max}$, $DP_{\max}$, SAC, branching factor, and polynomial degree.
The algorithms used were VEGA and SPEA.

\subsubsection{Parameters for Permutation}
First, evolution was performed with a population size of 100 and 1000 generations for a permutation
with four inputs and four outputs.

The VEGA algorithm reached an average individual\footnote{all values were rounded to two decimal places during typesetting}
with bent score $29.61$,
$-log_2{LP_{\max}} = 0.99$ i.e., $LP_{\max} = 0.5$,
$-log_2{DP_{\max}} = 1.31$ i.e., $DP_{\max} = 0.4$,
SAC $0.95$,
branching factor $2$,
and polynomial degree $2.77$.

The SPEA algorithm reached
bent score $31.50$,
$-log_2{LP_{\max}} = 1.91$ i.e., $LP_{\max} = 0.27$,
$-log_2{DP_{\max}} = 1.93$ i.e., $DP_{\max} = 0.26$,
SAC $0.98$,
branching factor $2.04$,
and polynomial degree $2.96$.

Neither algorithm reached any parameter that had any above-average individuals.
Therefore, considering the time complexity of the SPEA algorithm and based on results
from the program testing phase, different parameters were chosen:
200 generations and population size 200. The number of runs remained 100.
The values of the average individual were rounded down to whole tenths
before determining the counts of above-average individuals.

The VEGA algorithm reached this average individual:
bent score $29.1$,
$-log_2{LP_{\max}} = 1.7$ i.e., $LP_{\max} = 0.30778610333622908$,
$-log_2{DP_{\max}} = 1.5$ i.e., $DP_{\max} = 0.35355339059327379$,
SAC $0.2$,
branching factor $2.0$,
and polynomial degree $2.7$.
Table \ref{tabVegaParameters} lists the results for individual probability combinations.
The best combination was $pMut = 0.3$ and $pCross = 0.8$, although the counts were quite balanced.

The SPEA algorithm reached a slightly better average individual, similar to what was observed with a higher number
of individuals in the population:
bent score $31.6$,
$-log_2{LP_{\max}} = 1.9$ i.e., $LP_{\max} = 0.26794336563407328$,
$-log_2{DP_{\max}} = 1.9$ i.e., $DP_{\max} = 0.26794336563407328$,
SAC $0.9$,
branching factor 2.0,
and polynomial degree 2.9.
Table \ref{tabSpeaParameters} lists the results for individual probability combinations.
The best combination was $pMut = 0.9$ and $pCross = 0.05$.

Increasing the population size thus improved the averages of individual criteria.

\subsubsection{Parameters for i686}
The previous experiment was then performed with the i686 representation with four inputs
and four outputs. Additionally, a bijectivity score criterion was added,
since this representation does not guarantee bijectivity.

\section{Two-Phase Search}
To ensure bijectivity in CGP and i686 representations, another possible
solution\footnote{after bijective score as a criterion and bijectivity constraint in the objective
function}
is to divide the evolution into two phases.
In the first phase, the best solution is found using the permutation representation. This is then
used as a training set for symbolic regression using CGP or i686 representations.
Initially, there is a problem with selecting
a suitable candidate to proceed to the second phase. Symbolic regression will need
to be performed multiple times for several individuals. Furthermore, one must accept
the fact that symbolic regression also has its limitations and the problem is merely transferred to it.
Symbolic regression was performed
on CGP and i686 representations of dimensions $2 \times 2$, $4 \times 4$, $6 \times 6$, $8 \times 8$
on various permutations as training sets.
The training set is complete, i.e., it contains all inputs and outputs.

\subsubsection{Parameters of Symbolic Regression}
Already with a generation count of 50 and population size of 1000, solutions for $3 \times 3$ can be found
in the acyclic graph representation with 3 columns, 3 rows, and 3 maximum mutations, requiring
several runs. For more complex S-boxes, it depends on the function shape; for example, for
$f(x) =  x$ i.e., $[1, 2, \cdots, n - 1]$, a solution can be found without problem even for
$8 \times 8$.

A byproduct of this division can be optimal realization; however,
the fundamental criterion must be accuracy. The optimal solution is selected only from several
accurate solutions.

\section{Overall Evaluation of Results}
In single-criterion optimization on the performed experiments,
both random search and genetic algorithm
achieve nearly similar results. Only in some cases is one significantly better than the other.
In multi-criteria search using VEGA and SPEA algorithms,
it is easier to ensure better values of multiple criteria simultaneously
than with random search. While random search is algorithmically less complex,
genetic algorithm does not require as many runs (random initializations of individuals at the beginning).
Thus, there are cases of representations such as permutations where evolutionary algorithms can be used.
Bijectivity can be reliably guaranteed only for permutations. For other representations in multi-criteria search,
after adding the bijective score, the values of other criteria significantly deteriorate. And if
for all non-bijective individuals the value of each criterion is zero, i.e., first
a bijectivity test is performed and only then is the criterion calculated, this provides
even worse results. It would be best if for CGP and i686 representations there existed
genetic operators that would guarantee bijectivity.
For these representations, the complexity of their structures manifests itself (many possibilities
for mutation and crossover and the frequency of repetition of the same individual), and consequently
the evolutionary algorithm searches for solutions with more difficulty \cite{prednaskyBIN}.
Similar conclusions can be stated for finding minimal realization (according to the number of gates used) for the CGP representation, where
the population is contaminated by minimal non-functional circuits.
The division into two phases is merely a transfer of the problem to symbolic regression. Minimal
realization must be selected only after security criteria are met.
In the sources found, authors do not deal with multi-criteria search with multiple security
criteria.
In \cite{paretoHardware} they deal with optimal hardware structure, but security criterion
values are not mentioned.
